# Live Onboarding Companion (Deck Chair) — How It's Animated

This documents how `assets/live-onboarding-companion-eh0n.svg` (a round
mascot lounging in a deck chair, sunglasses on, drink in paw, with a
speech-bubble tooltip above it) became the `intro-loop` scene at
`public/projects/live-onboarding-companion-eh0n/scene-1/lottie.json`,
generated by `scripts/build-live-onboarding-companion-eh0n.mjs`. It reuses
every mechanism `companion-hug-animation.md` established (same bubble/trail
source shapes, same `intro-loop` marker contract, same native-text pattern) —
this doc only covers what's different: a "furniture" steady island (the
chair), a two-null lift-with-lag rig (the drink), a tilt-axis derived from
the source geometry instead of guessed, and a track-matte glint independent
of baked static highlights.

## Source material

`viewBox="0 0 240 240"`. The bubble/trail shapes (`Tooltip/Compact`, Ellipse
2420/2421) are pixel-identical in position to `companion-hug.svg`'s — same
trail chain, same plate top-left corner, only the plate width differs (176 vs
208, sized to this scene's shorter default string). Group `13308` (paint
order, later = on top):

- **Rectangle 767** — `chair-seat`, the big white fabric sweep (fill white,
  stroke `#222222`).
- **Vector 263 / 267 / 266** (painted *before* the seat) and **Vector 265**
  (painted *after* it) — four stroke-only diagonal lines. The brief calls
  these "crossed wooden legs"; the split paint order (three behind the seat,
  one in front) is exactly what sells the depth of an X-leg deck chair, so
  the layer names keep that distinction: `chair-leg-back-a/b/c` and
  `chair-leg-front`.
- **Group 1734** — the head, same bbox as `companion-hug.svg`'s `body`/`face`
  (`Fill 12` dark blob, `Fill 14` white patch — no separate eyes; the
  sunglasses sit where they'd be), plus the sunglasses: `Rectangle 765`
  (left lens, smaller x) / `766` (right lens), each with two white shine-
  slash strokes (`Vector 258/259` left, `260/261` right), and `Vector 262`,
  the dark bridge between them.
- **Ellipse 116** — `paw`, painted *first* in the group (i.e. backmost) —
  same "peeks from behind" idiom as `companion-hug.svg`'s paw, here reading
  as fingers wrapped behind the glass rather than in front of it.
- **Rectangle 768/769, Line 161, Vector 269, Vector 268** — the drink
  cluster, painted *last* (frontmost): glass outline (white fill), the dark
  drink fill, a straight straw, a small curved glass-shine accent, and the
  paper umbrella. All held out in front of the mascot by the paw.

## Chair: a steady island, literally furniture

Per the brief ("the chair and its legs never move — it's furniture"), the
seat and all four legs are `staticShapeLayer`s with no parent and no
animated properties at all — not even riding the head's recline. This is
the cheapest possible way to guarantee "never moves": there's no rig to
accidentally leak motion into them.

## Recline axis: derived from the chair's own geometry, not guessed vertical

The brief asks the body to sink "along the chair's tilt axis." Rather than
picking an arbitrary diagonal, the axis is computed from the source SVG's
own long crossing leg (`legBackC`, `Vector 266`, endpoints `(151.553,
105.344)` → `(85.1728, 225.999)`) — normalized to a unit vector and scaled by
a small `RECLINE_DIST` (3px). This guarantees the recline direction actually
matches the chair's drawn geometry instead of an eyeballed angle, and is a
reusable idea for any "move along this object's own slant" brief: pull two
points off an existing path in the source art and normalize, rather than
hand-picking degrees.

`head-rig`'s pivot is the head's own bbox bottom-center (its contact base
with the seat) — same "pivot at the contact edge" idiom as
`companion-hug.svg`'s `body-rig`, just bottom instead of side-edge since this
body sits *in* the chair rather than beside a pillow. Position translates
along the axis while rotation (`+2°`) sells "easing back," both riding the
same 3-keyframe rest→peak→rest hump (`T`, `T + IDLE/2`, `OP`) as
`companion-hug.svg`'s squeeze.

## Drink lift: two nulls, one authored curve, second one time-shifted

"Paw raises the drink... umbrella and straw riding along with ~2 frames of
lag" is authored as two separate transform nulls with the *same* offset
shape (`[3, -6]`, toward the face and up) rather than a nested parent chain:

- `drink-rig` parents `glass`, `drink-fill`, `paw`, `glass-shine` — keyframes
  at `DRINK_START`/`DRINK_PEAK`/`DRINK_REST`.
- `trailing-rig` parents `straw`, `umbrella` — identical keyframe shape, each
  `t` value `+2`.

This is the same "same curve, shifted `t`" trick `companion-hug.svg` used for
`arm-ring` lagging 2 frames behind `body-rig`'s squeeze — it generalizes
cleanly to "N objects riding one gesture with independent lag" without
nesting rigs inside rigs. All three drink-cluster tracks use the **sparse
keyframe** convention (first keyframe not at `T`, last not at `OP`) so rest-
before and rest-after come free from Skottie's hold behavior, exactly like
`companion-hug.svg`'s trail-circle stagger — no explicit `T`/`OP` bookend
keyframes needed when the value either side is simply "at rest."

## Glint: a dedicated matted overlay, never the baked shine slashes

The brief is explicit that "sunglasses shine slashes belong to the lenses,
never animated separately" — those four baked `Vector 258/259/260/261`
strokes stay static, parented to `head-rig` like everything else on the
head, with zero independent animation. The "at most one slow glint" is a
**separate, added** layer pair: `glint__matte` (an invisible filled copy of
the right lens, `td:1`) directly above `glint` (`tt:1`) — a small rotated
rounded-rect that slides across the lens center (`leftPos → midPos →
rightPos`) while its opacity ramps `0 → 34 → 0`, all inside a
sub-40-frame window early in the idle, clear of the sip beat. Track-matte
clipping means the sweep's exact travel distance doesn't need to match the
lens bounds precisely — anything outside the lens silhouette is invisible
regardless.

## Rig and timing

`T = 90` (1.5s intro — "nothing here is in a rush") / `IDLE = 180` (3.0s —
"longest, laziest period of the set") / `OP = 270` @ 60fps. Both numbers are
deliberately larger than `companion-hug.svg`'s (`T=72`/`IDLE=120`) to carry
the "unhurried," "vacation stillness" tone into the timing itself, not just
the easing.

- Trail: `trail-small` (r4, nearest the head) pops at `t:0`, `trail-large`
  (r8) at `t:8` — brief says "smallest first," reversed from
  `companion-hug.svg`'s stagger order (there it didn't matter which popped
  first; here it's a named requirement).
- Bubble: pop overshoots to 112% (vs. companion-hug's 108%) and takes longer
  to settle (`t:28→82` vs `t:18→58`) — a visibly lazier arrival for a
  visibly lazier brief.
- Recline peak at `T + IDLE/2` (`t:180`, dead center of the idle).
- Sip: rise `T+70`, peak `T+100`, rest `T+130` — centered slightly past the
  recline's peak so the mascot is already settled low in the chair when the
  paw lifts the drink, then both ease back toward rest together as the loop
  closes.
- Glint: `T+15 → T+35 → T+55`, well clear of the sip window.

## Loop-seam verification: the previewer's own frame clamp will lie to you

Diffing the previewer's rendered PNGs for frame `T` vs frame `OP` directly
(decoding both and comparing pixels) showed ~5,000 differing bytes in the
head region — looked like a broken seam. It wasn't: `preview-scene.mjs`
clamps every requested frame to `last = Math.ceil(op) - 1` before calling
`anim.seekFrame()`, because `op` is exclusive and frame `op` is never
actually displayed. Requesting frame `270` (`OP`) therefore silently renders
frame `269` instead — one frame *before* the authored rest keyframe, so an
easing curve that hasn't fully flattened out yet shows a few sub-pixel
antialiasing differences.

The correct check is to call `anim.seekFrame(T)` and `anim.seekFrame(OP)`
**directly** (bypassing the previewer's grid/clamp — a small throwaway
script, same pattern as `companion-hug-animation.md`'s "confirm via direct
pixel comparison"), which sample the keyframe tracks at the literal times
they were authored for. That comparison came back at exactly 0 differing
bytes across the full RGBA buffer. **Lesson: never diff `preview-scene.mjs`'s
own PNG output frame-for-frame to verify a loop seam — it clamps `op` to
`op - 1` for display purposes, which looks like drift that isn't there. Seek
`T` and `op` directly in a throwaway CanvasKit script instead.** This is
player-general (about the previewer tool, not this scene) and is now called
out in `player-contract.md`'s Intro + Loop section.

## v2 rework — idle-from-frame-0, text fidelity, denser secondary motion

`recipe-companion-bubble.md` changed after v1 shipped: the idle must run
continuously from frame 0 (not freeze during the intro), and it demands
"top-tier studio craft" density (overshoot, lag, wobble, a snappy accent at
its own beat). Three changes, `scripts/build-live-onboarding-companion-eh0n.mjs`:

### The "echo" technique for idle-from-frame-0

v1 authored every idle property as a single hump confined to `[T, op]`,
frozen everywhere in `[0, T)`. The fix is NOT a shorter cycle length (which
would have sped up the "slow contented" breathing to satisfy the intro
window) — it's recognizing that since rests already fall at `T` and `op`
exactly one period (`IDLE`) apart, the SAME periodic shape sampled at `t -
IDLE` is a valid earlier occurrence of the identical cycle. Concretely: take
each property's authored keyframe points, generate a second copy shifted
back by `IDLE`, drop any points that land at negative `t` (before the
composition starts), and prepend one explicit `t:0` rest so playback doesn't
snap to whatever value the first surviving point happens to hold. The result
is one continuous track — an "echo" occurrence bleeding through `[0, T)`
under the bubble/trail entrance, then the "real" occurrence inside `[T, op]`
— with **zero extra state to keep in sync with the seam**, because the echo
and the real occurrence are literally the same generator function
(`sipRun()`) called with different start times. This generalizes to any
per-cycle idle detail (recline, sip, wobble) without touching the cycle's
own tempo.

### Text fidelity bug: `anchor === position` always cancels to zero

The "sits high, renders thin" defect was two separate bugs given by one
line: `baseTransform({ a: [0, BASELINE_LOCAL, 0], p: [0, BASELINE_LOCAL, 0] })`.
Thin was the font weight (Regular instead of Bold — see below). High was a
transform-math mistake: with anchor `a` and position `p` set to the SAME
value, `screenPoint = S·(localPoint − a) + p` reduces to `S·localPoint + (p
− a) = S·localPoint + 0` — the `BASELINE_LOCAL` term cancels out of the
formula **regardless of what value it holds**. The baseline was landing
exactly at parent-local `(0,0)` (the plate's vertical center) every time, no
matter what "baseline offset" constant was chosen — which, for a string with
no descenders, reads as ink floating in the top half of the plate. The fix:
anchor at the text's own local origin (`a: [0,0,0]`, a stable pivot for the
pop-scale) and let POSITION alone carry the measured offset
(`p: [0, BASELINE_LOCAL, 0]`, held constant, not tied to the anchor). Verified
by rendering at 8x supersample and measuring ink rows within the plate
(excluding the plate's own 1.5px stroke border) — final `BASELINE_LOCAL =
5.41` lands both insets at exactly 12.000px. **Lesson: `anchor == position`
on a layer is not a no-op placeholder — it's a hidden zero, since the two
terms cancel in the transform formula. Never set them equal unless the
intent really is "no net translation."**

Font weight: swapped `fonts.list`/`textDoc().f` from `Nunito`/Regular to
`Nunito-Bold`/Bold (`fFamily` stays `Nunito`; only `fName`/`fStyle` change),
and copied `Nunito-Bold.ttf` next to the scene alongside a refreshed
`Nunito.ttf`. `fName` must equal the weight file's own basename — this is
also called out in the updated `recipe-companion-bubble.md` #2.

### Denser secondary motion: overshoot value, not overshoot curve

Per `motion-taste.md`'s "Skottie-safe" overshoot guidance, the sip's spring
is authored as an explicit **keyframe value** past the target
(`OVERSHOOT = DRINK_OFFSET.map(v => v * 1.35)`) that settles back to the true
`DRINK_OFFSET`, not a bezier easing curve with overshoot built in — this
stays robust under any Duration/speed rescaling the app applies. The
straw+umbrella's shared "wobble as they settle" is a small decaying rotation
on `trailing-rig` itself (so both layers inherit it for free), timed to
start exactly when the lift's position track returns to rest; the umbrella's
own additional "tiny extra rock" is a second, independent rotation on the
umbrella's OWN layer (own-center pivot, character-rig's idiom), timed to
start after the shared wobble resolves — secondary motion riding secondary
motion, each with its own beat. `trailing-rig` needed a real anchor (the
straw+umbrella cluster's bbox center) instead of the v1 `[0,0,0]` pure-
translate null, since a rotation now needs a pivot other than the canvas
origin — following head-rig's existing "anchor = pivot, position = pivot +
offset" pattern keeps `r:0` frames pure translation regardless.

## v3 fluidity pass — arc + drag, and a seam trap the fix nearly caused

`motion-taste.md` grew a **Fluidity** section (feature-animation bar for
mascots/held objects: continuous velocity through poses, arcs not straight
lines, drag not time-shifted-copy followers, anticipation+settle brackets,
verified by a "render every 2-3 frames and read the trail" spacing check).
The drink lift was the textbook violation this section targets — `sipRun()`
was a straight-line 2D tween, and `trailing-rig` was literally the same
`sipRun()` curve called with `t` shifted `+2` (the exact "time-shifted copy"
anti-pattern the section calls out by name). Three changes in
`scripts/build-live-onboarding-companion-eh0n.mjs`:

### Arc: spatial tangents (`to`/`ti`) are a separate axis from `ease`

`kf()`/`animProp()` only ever set `s`/`o`/`i` (value + **temporal** easing) —
there was no way to bow a position's PATH, only its speed along a straight
line. Added optional `to`/`ti` passthrough (Lottie's spatial bezier handles,
independent of the value-space easing bezier): `to` on the departing
keyframe, `ti` on the arriving one, both offset-vectors from that keyframe's
own value. The rise now leaves rest heading mostly vertical (`to: [0,
DRINK_OFFSET.y*0.55]`) and arrives at the overshoot from mostly horizontal
(`ti: [OVERSHOOT.x*-0.5, 0]`) — an up-then-across bow instead of a straight
diagonal. The descent gets its OWN independently-authored bow
(`FALL_TO`/`FALL_TI`), not the up-arc mirrored — asymmetric per-phase, per
the existing guidance.

### Drag: parent the follower, don't duplicate its keyframes

`trailing-rig` (straw + umbrella) is now parented DIRECTLY to `drink-rig`,
so it inherits the glass's exact translation at zero lag ("they move while
the glass moves") for free — no position track of its own at all. Its
anchor/position both sit at a fixed pivot (the cluster's own base — the
in-glass end, `bbox[3]` not `bboxCenter`), so the ONLY authored motion left
is a local rotation: lag-then-overshoot-then-decay, timed a couple frames
behind the glass's own beats and settling a beat after the glass itself
rests. Because the pivot is at the base, rotation alone gives "bends more at
the tip than the root" for free — no separate translation term needed.
**Generalizes**: a rider that's mechanically attached to its driver (a straw
in a glass, not a cape in the wind) is drag-by-rotation-about-the-attachment-
point on a child null, not a second position track.

### The spacing check catches things eyeballing a frame grid can't

`preview-scene.mjs`'s whole-scene grid renders the drink cluster too small
to read a ~9px arc. A throwaway cropped/zoomed CanvasKit script (clip to a
small SVG-space rect, scale ~15-18x) made it legible. But the more decisive
tool was evaluating the AUTHORED keyframes' actual bezier math directly (a
throwaway script implementing Lottie's temporal-bezier-then-spatial-bezier
composition, printing frame-by-frame position + delta magnitude) — it caught
two real defects invisible at a glance:

1. **A dead-stop-then-restart at a pass-through keyframe.** The rise-start
   keyframe (`v:[0,0]`) is a waypoint the anticipation swings back through,
   not a stop — but pairing an ease that DECELERATES into it (on the
   incoming segment) with one that ACCELERATES away from it (on the
   outgoing segment) made velocity crater to near-zero exactly there, then
   jump. Fix: use `exit-accelerate` (slow start, fast end) on the incoming
   segment so it arrives already fast, flowing into the outgoing segment's
   own fast start — continuous velocity through the waypoint. This is the
   general form of "ease-out into a pose plus ease-in out of it kills
   motion at every keyframe," just one keyframe subtler than the obvious
   case (here the pose ISN'T meant to be a stop at all).
2. **`travel-balanced` compressed into short stop-to-stop segments spikes.**
   The overshoot-to-peak correction (8 frames) and the hold-to-rest descent
   showed a real (not rendering-artifact) mid-segment velocity spike —
   confirmed by hand-evaluating the cubic bezier at the exact frame, not a
   script bug. `travel-balanced`'s control points (`1.00,.49,.00,.55`) are
   tuned for longer travel; swapping to a symmetric `.42,0,.58,1` for these
   short genuinely-stop-bounded segments produced a clean single bell curve.
   Promoted to `motion-taste.md`'s Easing Anchors section since it's a
   property of the anchor, not this scene.

### The seam trap: a periodic run's first point must be the true rest value

Adding the anticipation dip as literally the FIRST point of each `sipRun()`
occurrence broke the loop seam (`T` vs `op` went from 0 differing bytes to
3293) with zero visible symptom in any single-cycle preview — only the
direct-seek pixel diff caught it. Cause: the "echo" idle-from-frame-0
pattern depends on the long inter-cycle gap (previous rest to next cycle's
first keyframe) being a genuine flat `[0,0] -> [0,0]` hold, so that an
arbitrary point in the middle of it (`T` itself, which is nowhere near
either cycle's action) trivially evaluates to rest. Making the anticipation
dip's non-zero value the run's first point turned that entire ~100-frame gap
into a slow drift toward it — `T` landed mid-drift, no longer matching
`op`'s true rest. Fix: keep an explicit flat `[0,0]` point a short,
fixed lead (`ANTICIPATE_LEAD` frames) before the dip; the long gap before
THAT point stays truly flat regardless of how far back the previous rest
was. **Lesson, promoted to `player-contract.md`'s Intro + Loop section**:
any time a "leads into" beat (anticipation, a pre-roll wobble, anything
non-zero) becomes the first authored point of a periodic run, check whether
it just ate the flat rest plateau a loop seam or an idle-from-frame-0 echo
was depending on — the direct-seek pixel diff is the only check that
reliably catches it, since a single-cycle preview looks identical either
way.

## v4 — living idle + stage safety

`motion-taste.md` grew a "Living idles — the Rive-grade bar" block (Fluidity
section) and a stage-safety rule (Render-Aware Motion). This pass rebuilt
the idle as a motion SYSTEM per that bar, and fixed a real localization bug
(a Polish string clipped the stage's left edge because the bubble sat
off-center). Architecture ported from `scripts/build-loop-zenek-our-pexy.mjs`
— its `evalTrack`/`tileCycle` (dense cubic-bezier track evaluation + forward
tiling) — combined with this file's own echo technique for backward
extension into `[0, T)`.

### Four shared clocks, non-trivial ratios

| clock | period | cycles/loop | drives | peaks at (abs frame) |
| --- | --- | --- | --- | --- |
| `CLOCK_BREATHE` | 90f | 2 | head-rig position+rotation+scale (primary); chair-seat squash (derived) | 128, 218 |
| `CLOCK_GLINT` | 60f | 3 | sunglass glint sweep | 114, 174, 234 |
| `CLOCK_SIP` | 180f (=IDLE) | 1 | drink-rig sip arc (unchanged v3 mechanism) | ~188 (overshoot) |
| `CLOCK_DETAIL` | 36f | 5 | head-rig secondary micro-wobble (riding rotation) | 106, 142, 178, 214, 250 |

All four divide `IDLE=180` exactly (180/90=2, /60=3, /180=1, /36=5). Ratio
90:60:180:36 reduces to 15:10:30:6 — not a 1:2:4 pattern, so the clocks drift
in and out of phase with each other rather than landing in lockstep. Peak
frames were computed, not guessed, and hand-checked pairwise for near-misses
(closest pair is glint@174 vs sip-overshoot@188, 14 frames apart — no two
clocks share an exact beat).

### Motion is a function; keyframes are its samples

Two new house helpers (near `kf`/`animProp`), both lifted from the zenek
script: `bezierEaseFn` + `evalTrack` (evaluate a point-track's real
cubic-bezier easing at an arbitrary `t`, not just at authored keyframes) and
`tileForward` (zenek's `tileCycle`, renamed to pair with the new
`echoBackward`). `echoBackward` generalizes THIS file's existing echo trick
(previously a one-off inline pattern per property) to periods that don't
evenly divide `T=90`: `CLOCK_GLINT` (60) and `CLOCK_DETAIL` (36) both need
**two** backward cycles to fully cover `[0, 90)`, not one — the helper loops
`cycleStart -= period` until a cycle can no longer contribute any `t >= 0`
point, so it degrades to the old single-echo case automatically when a
period does evenly divide `T` (e.g. `CLOCK_BREATHE=90`). The one precondition
this generalization needs: each cycle's local shape must REST at both local
`0` and local `period` (a short active window, flat before/after) — the file
already had this property everywhere from earlier passes (a snappy accent
bounded by rest), so it was free to lean on.

### Amplitude that reads (the actual defect this pass kills)

Old breathe: `RECLINE_DIST=3px` / `RECLINE_ROT_DEG=2deg` — well under the
"~3% of comp min-dimension" floor (3% of 240 = 7.2px), genuinely
imperceptible at normal playback speed. New: `RECLINE_DIST=9px` (3.75%),
`RECLINE_ROT_DEG=4deg`, plus a NEW `BREATHE_SCALE_AMP=3%` chest-swell riding
the same envelope — three properties off one function, not three hand-tuned
curves. `DETAIL_ROT_DEG=1.6deg` (secondary, clearly quieter than the 4deg
primary, per Choreography's primary/secondary hierarchy).

### The world responds (derived, not independent wiggles)

Three response relationships, each literally evaluating or reusing an
existing generator rather than hand-authoring an independent curve:

1. **Chair-seat squash** — `chair-seat` samples the SAME `breatheEnvelope(t)`
   head-rig uses (zero lag: a direct reaction to weight, not a delayed
   echo), mapped to `[100+1%*env, 100-3%*env, 100]` scale, pivoted at the
   seat's own top-center (its contact point with the mascot) so it reads as
   sinking, not shrinking evenly. The rigid leg struts stay exactly the
   pre-v4 steady island (unparented, unanimated) — only the fabric flexes.
2. **Liquid slosh** — `drink-fill` gets its own small rotation from
   `liquidRun()`, which is `dragRun()` (the SAME generator already driving
   straw/umbrella) re-mapped through a `0.45` amplitude gain and 3 extra
   frames of lag. This makes the reaction chain explicit in the code itself:
   glass moves -> straw/umbrella drag (v3) -> liquid slosh (v4, derived from
   the drag, not from the glass directly) — the innermost, softest link.
3. **Glint's own beat** — retimed from a single per-loop occurrence to its
   own tiled `CLOCK_GLINT`, phased so its peaks (114/174/234) don't land
   within a few frames of breathe's or detail's — "a beat no other clock
   peaks on," verified by literally listing all four clocks' peak frames
   and checking pairwise gaps (see table above).

### Stage safety: the bubble was off-center and the math showed it

`PLATE_CX` was `102` — not stage-center (`120`) — leaving only `102-16=86px`
of safe half-width before the LEFT edge violated the `>=16px` margin, vs.
`240-102-16=122px` on the right. That asymmetry is exactly what a longer
Polish string clipped. Fix: recenter to `PLATE_CX=120` (symmetric,
`max[0]=2*(120-16)=208`) and shift the trail circles by the same delta so
the "leads to the mouth" chain stays intact.

Vertically the fix is tighter: `max[1]=73` (3 lines) needs `36.5px` of
half-height, and the mascot's head top sits at `y=98.6` (`bboxOf(headDark)`)
— an 82.6px band between the 16px top margin and the head, into which a
73px-tall plate barely fits. `PLATE_CENTER_Y=54` was chosen so the top edge
(`54-36.5=17.5`) clears the margin with 1.5px to spare and the bottom edge
(`54+36.5=90.5`) clears the head with 8.1px to spare — genuinely tight, but
real, headroom on both sides. **This is why the recipe's `max[1]` isn't just
a number to plug in: it constrains where the plate's CENTER is allowed to
sit, and that constraint can be nearly as tight as the stage itself on a
small (240px) canvas.** Verified two ways: rendering the motion extremes
(breathe/glint/sip peaks, above) shows generous clearance since the mascot
itself never rises above its own rest position; and a throwaway bake with
the brief's Polish string (`Świętujemy dobre procesy`, measured via
CanvasKit's `Font.getGlyphWidths` at 194px full-width vs. the design
string's 144px — wraps to `['Świętujemy dobre', 'procesy']` at `166x54`,
comfortably under `max`) rendered fully inside the stage with margins to
spare in every direction, text centered on both axes.

**Multi-line vertical centering**: the measured `BASELINE_LOCAL=5.41` (from
the v1 pass) is tuned for ONE line. For N lines, shift the whole text
layer's position up by `(N-1) * LINE_HEIGHT / 2` so the multi-line block
centers on the same reference point the single-line case used — confirmed
in the throwaway bake (2 lines, shifted up by `19/2=9.5px`). **Superseded by
v5's `bubble.textPos` slot below** — this scene no longer needs a bespoke
per-scene formula promoted into `textDoc`'s call site; the slot is the
portable mechanism every companion scene now ships.

## v5 — key-exactly-on-boundaries, and the `.textPos` slot

Two contract items landed in the shared references
(`motion-taste.md`/`recipe-companion-bubble.md`) that this scene hadn't
caught up to yet.

### The seam wasn't actually closed — endpoint/keyframe checks lie

`motion-taste.md`'s Living-idles bar grew a fifth rule: **key exactly on the
loop boundaries — never span them.** Every animated track needs an EXPLICIT
keyframe AT `T` and AT `op` with equal values — a segment that merely
CROSSES the boundary (a keyframe before, a keyframe after, none exactly on
it) makes the value AT `T` an interpolation, not a keyed fact. The v4 pass's
`sipRun`/`dragRun`/`livingTrack`-based tracks (`drink-rig`, `trailing-rig`,
`drink-fill`, `umbrella`, `glint`) all had exactly this shape: an echo tail
ending well before `T`, the next real cycle's first point starting well
after `T`, nothing keyed exactly on `T` itself. **Every one of them still
passed a T-vs-`op` PIXEL diff (0 differing bytes) and a per-property
value-at-T-vs-value-at-op audit**, because in every case the echo's tail and
the real run's first point both happen to already BE the track's rest value
(`[0,0]` for the sip/drag/liquid/rock tracks, `rightPos` for glint) — so the
interpolated value anywhere in that gap, including at `T`, is trivially
that same rest value too. The match was real but INCIDENTAL: nothing in the
code guaranteed it, so a future edit to any amplitude, offset, or timing
constant in `sipRun`/`dragRun`/`rockRun`/`liquidRun` could silently break it
with no test catching the change (a pixel diff only tells you TODAY's
values match, not that they're structurally guaranteed to keep matching).
**Lesson: passing a pixel diff is necessary but not sufficient — it doesn't
distinguish "this track is keyed on the boundary" from "this track happens
to be flat across a span that includes the boundary." Audit keyframe
TIMES (does an explicit key exist at exactly T and exactly op?), not just
values, and treat a coincidental match as a bug waiting for the next edit.**

Fix: a new `keyOnBoundaries(points, restValue)` helper (next to `kf`/
`animProp`/`livingTrack`) inserts an explicit `{t: T, v: restValue}` and/or
`{t: op, v: restValue}` into any points array missing one, no-op wherever a
boundary key already exists. Applied to EVERY animated track in the file —
including the one-shot intro tracks (bubble pop/opacity, trail pop/opacity)
that settle well before `T` and were never at risk of the spanning failure
mode, for the same "guaranteed, not incidental" reason. `head-rig` and
`chair-seat`'s dense-sampled tracks were the one exception left untouched:
their sample step (6f) already divides both `T=90` and `op=270` evenly, so
they were already keying exactly on both boundaries by construction — adding
a redundant wrapper there would touch working code for no benefit.

For `glint` specifically, `keyOnBoundaries` runs BEFORE the existing
`hold`-marking step (from the previous pass's fix), not after — so a newly
inserted `t:T` point with `v = rightPos` still gets picked up by the
value-match `.map()` that marks every `rightPos`-valued point held. Ordering
matters here: insert the missing structural anchor first, then apply
whatever per-value treatment the track needs.

### The `.textPos` slot: the only working multi-line centering mechanism

`recipe-companion-bubble.md` documents why the "obvious" fix for multi-line
vertical centering doesn't work: the text-document's `ls` (baseline shift)
field is **silently ignored by Skottie** (measured: `±9.5` and `0` render
byte-identical). The mechanism that DOES work is a slot on the text layer's
own `ks.p` (position), not on the text document. Added:

- `doc.slots['bubble.textPos']`, defaulting to `[0, BASELINE_LOCAL, 0]` —
  the exact single-line value this scene already used, so nothing about the
  default render changes.
- `bubble-text`'s `ks.p` now carries `sid: 'bubble.textPos'` instead of a
  bare literal.
- A `controls.json` entry, `{ sid: 'bubble.textPos', internal: true }` —
  `internal` marks it as layout plumbing (driven by wrap math when a tool
  wraps `bubble.text` onto multiple lines, shifting this slot's y by
  `-(lines-1)*lineHeight/2`) rather than something exposed as an editable
  field the way `bubble.text`/`bubble.size` are.

This scene's build script does NOT perform the wrap-time shift itself —
that's a tool-side concern (measure the string, decide the line count,
compute the offset, write the override). The script's job is only to
publish the slot with the correct calibrated default and bind the layer to
it, which is what makes the mechanism available at all.

## Applying this to a different companion/bubble SVG

1. **When a brief names a motion axis tied to the source art ("along the
   chair's tilt", "along the ramp", "following the wing's angle"), pull two
   points off the actual source geometry and normalize** — don't guess an
   angle. Cheap, and it's guaranteed to match what's drawn.
2. **A rider mechanically attached to its driver (a straw in a glass, an
   ear on a head) is drag-by-rotation on a child null parented to the
   driver, pivoted at the attachment point — never the driver's own
   keyframes copied and `t`-shifted.** A shifted copy reads as a detached
   lag, not drag (see the Fluidity section of `motion-taste.md` and the v3
   pass below); parenting gives zero-lag translation for free, and rotation
   about the base-not-center pivot gives "bends more at the tip" for free.
3. **A "never moves" brief requirement (furniture, background, chrome) is
   best satisfied by giving those layers no parent and no animated
   properties at all**, not by parenting them and manually zeroing every
   track — there's nothing to accidentally leak. Where a later brief adds
   life to part of that object (v4: the chair's fabric SEAT flexes, but its
   rigid leg struts still never move), keep the distinction at the layer
   level — animate only the part that's alive, leave the rest exactly as
   this rule describes.
4. **A new one-off accent (a glint, a sparkle, a highlight) that shares a
   surface with existing static baked strokes should be its own matted
   overlay layer**, never a reuse/re-animation of the baked strokes — keeps
   "never animated separately" briefs honest and keeps the effect removable
   without touching the base art.
5. **Never verify a loop seam by diffing `preview-scene.mjs`'s PNG output for
   frame `T` vs frame `op`** — its clamp renders `op` as `op - 1`. Seek both
   frames directly in a throwaway CanvasKit script for a true pixel diff.
6. **An organic move's position track needs spatial tangents (`to`/`ti`) to
   arc, not just eased timing** — `ease` alone only reshapes speed along a
   straight line between keyframes; the PATH itself needs the spatial
   bezier handles authored separately (see kf()'s `spatial` param).
7. **Before trusting a rendered frame-grid's read on a small/subtle move,
   hand-evaluate the authored keyframes' actual bezier math** (temporal
   ease composed with spatial bezier) frame-by-frame and print delta
   magnitude — it catches dead-stops-at-pass-through-poses and short-
   segment easing spikes that a whole-scene PNG grid is too small to show
   and that aren't always obvious even zoomed in.
8. **Adding a new non-zero lead-in keyframe (anticipation, a pre-beat wobble)
   as the FIRST point of a periodic run can silently break a loop seam** if
   anything (an idle-from-frame-0 echo, the seam pair itself) was depending
   on the gap before that run being a flat hold at the true rest value —
   re-run the direct-seek seam diff after any such change, since a normal
   preview looks unchanged either way.
9. **A "world responds" reaction (chair flexes, liquid sloshes, shadow
   breathes) should evaluate or re-map the SAME generator/track driving its
   source, never a hand-authored independent curve with matching timing** —
   `chair-seat` samples `breatheEnvelope(t)` directly; `drink-fill`'s slosh
   is `dragRun()` itself re-mapped through a gain and extra lag, not a new
   curve that happens to look similar. This is what keeps a derived reaction
   provably in-phase (or deliberately, traceably offset) rather than
   coincidentally close.
10. **When two+ independent periodic clocks must combine onto ONE property**
    (a layer only has one `r`/`p`/`s` track), dense-sample both envelope
    functions at a fixed step (the zenek script's own `SAMPLE_STEP=6`
    convention) and SUM the contributions per-sample — don't try to
    hand-interleave two keyframe lists with different periods into one
    track. This is also a cheap, reliable way to hit the "keyframe density
    in the hundreds" bar the Living-idles rule asks for.
11. **A bubble/plate's `PLATE_CX` should be checked against the true stage
    center, not just "does the default string fit"** — an off-center plate
    can pass every check at the design string's width while silently having
    almost no margin on whichever side it's biased toward, and a longer
    translation is what finds that the first time. Compute `max[0]` from
    the ACTUAL plate x-position (`min(cx, stageW-cx) - margin) * 2`), not
    from an assumed centered stage width — and recenter or budget more
    margin for whichever edge is closer.
12. **A periodic idle track must carry an EXPLICIT keyframe at exactly `T`
    and exactly `op`, never merely a segment that spans across them** —
    even where a spanning segment's two neighboring keyframes already
    happen to share the same rest value (echo tail / next cycle's start
    both at `[0,0]`, say), that's an incidental match a pixel diff and a
    value-at-T-vs-value-at-op audit both rubber-stamp, not a guarantee that
    survives the next edit to the same generator's timing or amplitude.
    Insert the boundary keyframe explicitly (a small reusable helper —
    `keyOnBoundaries()` — rather than hand-checking each track).
13. **`ls` (baseline shift) on a Lottie text document does not work in
    Skottie** — multi-line vertical centering needs a slot on the text
    LAYER's own position (`ks.p`, `sid: 'something.textPos'`), defaulted to
    the already-calibrated single-line value so the file's default render
    never changes. The build script's job stops at publishing the slot
    correctly (default value + `sid` binding + an `internal: true` controls
    entry) — computing the wrap-time `-(lines-1)*lh/2` offset is tooling's
    job, not the scene's.
