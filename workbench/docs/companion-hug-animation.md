# Companion Hug — How It's Animated

This documents how `assets/companion-hug.svg` (a round mascot hugging a
heart-marked pillow, with a speech-bubble tooltip above it) became the
`intro-loop` scene at `public/projects/companion-hug/scene-1/lottie.json`,
generated by `scripts/build-companion-hug.mjs`. It's the first scene in this
project to ship a **native `ty:5` text layer with a text slot**, and the
first `intro-loop` kind built from scratch — most of what's below is
player-general and has been promoted into the skill references (see the end
of this doc); treat this as the worked example those references point back to.

## Source material

`viewBox="0 0 240 240"`, one `<g>`, paint order (later = drawn on top):

- **Tooltip/Compact** — a stroke-only (`fill:none`, inherited from the root
  `<svg fill="none">`) rounded rect, `rx 17.5`, `stroke-width 1.5`, plus a
  baked-outline `font` path for the label text.
- **Ellipse 2420 / 2421** — two small stroke circles between the bubble and
  the mascot's head. The brief names these the "trail" the bubble grows
  from; this source has no separate tail triangle, so the trail circles
  *are* the tail-equivalent (recipe-companion-bubble.md's "tail" role).
- **Group 1000007767** (mascot + pillow), containing, in this order:
  - **Ellipse 324** — a small filled circle, positioned *before* the body/
    face group, i.e. painted **behind** it: a paw peeking out from the hug.
  - **body / face / Vector 1 / Vector 2** — the mascot's head: a solid
    circle, a white face patch, and two open-stroke arcs for closed, happy
    eyes (`Vector 1` sits left-of-center, `Vector 2` right-of-center —
    confirmed by bbox, not by the generic names).
  - **"charity stone" (+ "_2")** — the pillow: one filled+stroked blob plus
    two white stroke creases.
  - **"Union"** — a small heart, authored twice (a plain fill path, and a
    near-duplicate with far more anchors that's the source's
    stroke-expanded-to-fill twin of the same outline). Only the simpler of
    the two was ported; at this scale the second is visually redundant.
  - **Ellipse 325 / Vector 1012** — white stroke arcs, painted *after* (in
    front of) both body and pillow: the visible hugging arm and a secondary
    highlight crease.
- **"Fill 11"** — a flat pill shape filled with a raster `<pattern>`
  (`fill-opacity 0.15`) tiling an embedded 128×128 PNG. Decoding the PNG
  (`base64 → file`, then just opening it) showed a plain 45°
  diagonal-line hatch — the ground shadow.

Rendering the raw SVG first (a throwaway CanvasKit script, one `fillPath`/
`strokePath`/`strokeCircle` call per element, discarded after) turned the
above from a guess into a confirmed map before any Lottie code was written —
see svg-compatibility.md's "render the SVG statically first" step. This
composition is dense enough (16 shape elements plus a raster pattern) that
skipping this step would have meant misreading at least the paw-behind-body
stacking and the heart's double-path authoring.

## The two player-general discoveries

Both of these came from watching the *previewer*, not the animation, behave
wrong — worth restating since neither is obvious from the Lottie spec alone.

### 1. The headless previewer didn't load fonts — native text needs `assets`

`scripts/preview-scene.mjs` called `ck.MakeManagedAnimation(LOTTIE, null)`.
With no font bytes supplied, a `ty:5` text layer doesn't render blank — it
renders a **visible dark placeholder shape pinned at the composition's
absolute origin (0,0)**, unconditionally, on every frame, regardless of the
text layer's own transform. First render of this scene showed exactly that:
a small black blob glued to the top-left corner of every frame, present even
before the bubble had appeared. It looked like a stray shape bug in the rig;
it was a missing-font indicator.

The fix (now permanent, in `preview-scene.mjs`): mirror the app player's own
asset pipeline (`workbench/src/lib/scene.ts`) — read every `.ttf`/`.otf`/
`.ttc` (and image) file sitting next to `lottie.json`, keyed by bare
filename, and pass that dict as `MakeManagedAnimation`'s second argument.
Confirmed: for fonts the dict **key is arbitrary** — CanvasKit resolves each
text layer by the font's *embedded family name* against `fonts.list[].fFamily`,
not by the key or filename. Images still need to key-match `assets[].p`
exactly. This means **any scene using native text must ship its font file
next to `lottie.json`** (not just in a shared `assets/fonts/` folder) for
both the app player and this previewer to render it — copied here as
`public/projects/companion-hug/scene-1/Nunito.ttf`.

### 2. A parented text layer inherits the parent's animated position, not its scale

The bubble's pop-in was authored as a single scaling null (`bubble-anchor`)
with the plate and text both parented to it, expecting both to grow
together automatically. The plate did; the text didn't — at frame 20 (parent
still ~15% scaled), the plate rendered as a tiny pill while the text
rendered at **full final size**, floating free of it. Position composed
correctly (the text was in the right place), only size didn't.

Confirmed workaround: give the text layer **its own explicit scale
keyframes** (the same curve as the parent's, pivoting at the text's own
anchor point) instead of relying on inherited parent scale. Position
inheritance through parenting is unaffected and still the simplest way to
place text relative to a moving/scaling group — just don't expect *size* to
come along for free.

## Bubble entrance: pivot at the plate's bottom edge, not its center

`recipe-companion-bubble.md` asks for the bubble to "emerge from the trail."
A scale-from-0 on a null anchored at its own center just grows outward from
the middle, with no visual connection to the trail below it. Instead,
`bubble-anchor`'s anchor point is set to the plate's **local bottom-center**
(`[0, PLATE_H/2]`) while its `p` is set to the plate's bottom-center *in
composition space* (`[118, 49]`, matching the trail circles' region):

```js
ks: {
  a: { a: 0, k: [0, PLATE_DEFAULT_H / 2, 0] },   // local bottom-center
  p: { a: 0, k: [PLATE_CX, PLATE_BOTTOM, 0] },   // where that point lands
  s: animProp(BUBBLE_POP...),                     // scale-from-0 here
}
```

At any scale, the anchor point itself stays pinned at `(118, 49)`; every
other point on the plate (including its center, above the anchor) scales
toward or away from that pin. The result reads as the bubble growing
*upward* out of the trail chain rather than inflating from its own middle —
reusable for any speech-bubble/tooltip entrance, not just this one.

## Trail + bubble: one authored track, staggered by start time

`animProp()` here deliberately does **not** force a `t:0` keyframe (unlike
the character-rig house pattern's `ensureStartsAtZero`) — Skottie holds a
property at its first keyframe's value for every earlier frame, so a track
that starts at `t:18` is implicitly invisible/at-rest from frame 0 to 18 for
free. That's what staggers the three pop-ins (`trail-small` at `t:0`,
`trail-large` at `t:6`, the bubble at `t:18`) without any explicit "hold"
keyframes:

```js
trailCircle('trail-small', 114, 84, 4, [{ t: 0, v: 0, ... }, ...])
trailCircle('trail-large', 102, 66, 8, [{ t: 6, v: 0, ... }, ...])
```

Text fades and pops with the plate as one unit — same `BUBBLE_OPACITY`/
`BUBBLE_POP` arrays reused on both layers, per recipe-companion-bubble.md's
"the bubble text does not animate per-glyph."

## Shadow: raster hatch pattern revectorized, breathing as one piece

The source's raster diagonal hatch (see above) is exactly the "raster
`<pattern>` fill" case svg-compatibility.md warns never to flatten to a
solid. Revectorized as ~30 parallel 45° stroke segments (`y = x - c` for
stepped `c`, spanning the shape's bbox plus margin) at the source's
`fill-opacity 0.15` → Lottie stroke opacity `15`, clipped to the true pill
silhouette via a track matte (`shadow__matte`, `td:1` → `shadow`, `tt:1`).

Both the matte and the hatch are parented to one `shadow-rig` null that
carries the idle "breathes opposite the body" scale. Because the hatch is
clipped *after* the whole rig's transform is applied, scaling the null
scales the matte and the texture together as one piece — which is exactly
the desired look here (the texture never needs to slide independently
inside its clip), so this is the rare case where "rasterize once, scale as
a whole" (svg-compatibility.md's fallback path) and "revectorize" aren't in
tension — revectorizing was cheap and preserves crispness at any preview
zoom, so it won out over pre-rendering a PNG.

## Rig and timing

`T = 72` (1.2s intro) / `IDLE = 120` (2.0s hug-breathe) / `op = 192` @ 60fps.

- **`body-rig`** (null, anchor = pivot at the body's contact edge with the
  pillow, its rightmost point mid-height): parents `body`, `face`,
  `eye-left`, `eye-right`. Idle: `scaleX 100→96→100`, `scaleY 100→103→100`,
  peaking at `T+45` — compresses the head toward the pillow, volume-
  preserving. Eyes ride this AND get their own additional own-center
  `scaleY` dip (character-rig recipe's blink idiom) for "eyes arc subtly
  with the squeeze."
- **`arm-ring`** + **`paw`**: independent own-center scale dips, peaking at
  `T+47` — 2 frames after the body's `T+45` peak, per the brief's "~2 frames
  of overlap." Everything else on the pillow (`heart`, `pillow-crease`,
  `arm-crease`, `pillow` itself) is a steady island: unparented, unanimated
  — motion economy over deforming every element "because it's nearby."
- **`shadow-rig`**: `scaleX 100→106`, `scaleY 100→102`, **also** peaking at
  `T+45` (same frame as the body) — "wider as the body settles" means widest
  exactly when the squeeze is deepest, not phase-shifted.
- Every idle track's first keyframe sits at `t:T` and last at `t:OP` with
  identical values (`100` / rest) and symmetric easing on both sides of the
  single mid-cycle peak — confirmed pixel-identical via a direct byte
  comparison of a `seekFrame(72)` vs `seekFrame(192)` render (0 differing
  bytes across the full RGBA buffer), not just eyeballed.

## Layer map (front-to-back)

```
bubble-plate, bubble-text          (parented to bubble-anchor)
bubble-anchor                      (null — intro pop, pivot at plate bottom)
trail-large, trail-small           (independent pop-ins, staggered start)
arm-crease, arm-ring               (arm-ring animated, crease static)
heart, pillow-crease, pillow       (steady island)
eye-right, eye-left, face, body    (parented to body-rig)
body-rig                           (null — idle squeeze)
paw                                (independent tighten, syncs with arm-ring)
shadow__matte, shadow              (matte pair, parented to shadow-rig)
shadow-rig                         (null — idle breathe, opposite phase)
```

## Applying this to a different companion/bubble SVG

1. **Render the raw SVG once before writing any Lottie code** when the
   composition has more than a handful of elements or any ambiguous
   grouping (paw-behind-body, the heart's double path) — a throwaway
   CanvasKit script, discarded after, is much faster than guessing from
   coordinates and getting stacking or identity wrong.
2. **Any scene with native text must ship its font file inside the scene
   folder**, not just reference a shared `assets/fonts/` copy — both the app
   player and `preview-scene.mjs` only discover fonts sitting next to
   `lottie.json`.
3. **Don't assume a parented text layer scales with its ancestor.** If a
   text layer needs to visually pop/grow with a group, give it its own
   explicit scale keyframes; only trust inherited *position* through
   parenting for text.
4. **Pivot a bubble's intro scale at its own edge nearest the tail/trail**,
   not its center, so growing-from-0 reads as emerging from the trail
   instead of inflating from the middle.
5. **Use un-zeroed keyframe tracks (first keyframe at the actual start
   time, not `t:0`) to stagger independent pop-ins for free** — Skottie's
   hold-before-first-keyframe behavior does the "wait, then pop" for you.
6. **A raster hatch/pattern shadow that only needs to scale as a whole**
   (not deform independently of its clip) is a good candidate for
   revectorizing into a track-matted stroke cluster rather than
   pre-rendering a PNG — same fidelity, stays crisp at any zoom.
7. **Confirm a loop seam by direct pixel comparison** (`seekFrame(T)` vs
   `seekFrame(op)`, diff every byte), not just by eye — it's the only way to
   be sure "looks the same" is actually "is identical."
